P|A security control is an action or mechanism that changes risk. Classify it on two separate axes: who or what implements it, and what outcome it produces. A badge system can be technical because software enforces access and preventive because it rejects unauthorized entry. A guard checking the same badge is operational; the fence surrounding the site is physical. Choosing one axis does not erase the other.
P|Purpose depends on the described use, not the device name. A camera recording evidence is detective; a prominently displayed camera intended to discourage trespass is deterrent. Do not invent an event or restriction that was never stated.
P|A UPS (Uninterruptible Power Supply) bridges loss of normal power. It is physical by implementation and supports availability. When framed as substitute power after utility failure, it can be classified as compensating; repairing a damaged system afterward is corrective. T|Managerial|Leadership establishes requirements, oversight, risk decisions, and policy. Approving a security program is managerial; technicians implementing its settings are performing a different part of that program.
T|Operational|People execute security processes such as checking visitors or reviewing alerts. A computer may assist them, but the described safeguard depends on human performance rather than automatic enforcement.
T|Physical|Tangible measures protect facilities and equipment: locks, barriers, generators, and protected enclosures. Physical describes implementation, not whether the measure prevents, detects, or restores.
T|Preventive|Blocks an unwanted event before it succeeds. A permission check denies a write; an interlock stops entry. Compare with detection, which notices the attempt but need not stop it.
T|Detective|Discovers or records activity for investigation. A sensor or review identifies a problem. Detection does not by itself remove the threat or restore the service.
T|Corrective|Repairs an unacceptable state after a problem. Rebuilding a damaged system or restoring a backup is corrective. It differs from arranging an alternative safeguard before damage occurs.
T|Deterrent|Discourages a person from attempting an action through perceived observation or consequences. Warning notices may deter without technically preventing the behavior.
T|Compensating|Provides alternative protection when the intended safeguard cannot be used. Identify the unavailable control and the substitute. A substitute must address the risk; merely adding another unrelated tool is insufficient.
T|Directive|Specifies required or prohibited behavior through instructions, policy, or standards. It tells people what to do; an enforcement mechanism may separately prevent violations.

P|Separate the security outcome from the access process. Confidentiality asks who can read; integrity asks whether data was changed; availability asks whether the service is usable. Authentication establishes who is presenting a claim. Authorization evaluates what that identity may do. Accounting records what happened. A successful login is not permission to open every resource.
P|Digital signatures can support both integrity and origin authentication. A question about detecting message modification points to integrity; a question about validating the signer points to authentication. Non-repudiation adds evidence against later denial, assuming keys and identity binding are trustworthy. An ordinary unkeyed hash from an untrusted source does not establish who created the file. Zero trust evaluates each access request using identity, device, and policy instead of assuming an internal network location is enough.
F|Identify the asset|Identify the required outcome|Separate identity from permission|Choose the evidence that demonstrates it
T|Confidentiality|Restricts disclosure to authorized parties. Encryption and read permissions can protect it. A file may remain confidential yet be corrupted, so secrecy does not establish integrity.
T|Integrity|Protects against or detects unauthorized alteration. Trusted hash comparisons and signatures can reveal changes. Integrity does not guarantee that an unchanged file is harmless or truthful.
T|Availability|Keeps a service accessible when needed through capacity, redundancy, recovery, and operational maintenance. A secure inaccessible system can still fail this goal.
T|Authentication|Verifies an identity claim using an authenticator or trusted identity assertion. It precedes access decisions but does not grant every possible permission.
T|Authorization|Determines which actions an identity may perform on a resource. The decision can depend on role, attributes, resource sensitivity, and current context.
T|Accounting|Records actions, sessions, and resource usage for traceability. Logging a command supports investigation but does not itself prove that the command was permitted.
T|Non-repudiation|Provides evidence connecting an action to a party to counter denial. A protected signing key with a trustworthy identity binding is stronger evidence than a shared password.
T|Zero trust|Removes implicit trust based only on location or ownership. Access is evaluated using policy and context with limited privileges, and may be reevaluated as risk changes.
T|Policy enforcement point|Allows, blocks, or terminates access according to a policy decision. The point enforces; the policy engine evaluates criteria and the policy administrator establishes or ends the connection.
T|Honeypot|A decoy resource attracts and records suspicious interaction. It is not a substitute for protecting production systems, and legitimate traffic must not accidentally depend on it.
E|A technician signs in successfully, receives permission to view one project, and has each download recorded. That sequence is authentication, authorization, accounting. If a downloaded plan is secretly altered, integrity has failed even though login worked. If the plan is leaked, confidentiality fails. If the plan cannot be retrieved during an outage, availability fails.

P|A change is a controlled transition from a known state to a new state. Start with the business requirement and dependencies, analyze effects, test, obtain the appropriate approval, communicate, implement in the approved window, and validate. Emergency procedures may accelerate authorization but do not make accountability and documentation disappear. A successful installation message is not proof that the business workflow still works.

P|Encryption reversibly transforms plaintext using a key. Symmetric encryption uses a shared secret and handles bulk data efficiently. Asymmetric cryptography uses a related public/private pair and supports key establishment and signatures. Hashing produces a fixed-length digest and is not reversible encryption. A trusted matching hash supports integrity, but an unchanged malicious file is still malicious. Always ask what property is required: secrecy, change detection, signer identity, or recovery.
P|With a digital signature, a private key signs and a public key verifies. To send encrypted data using public-key encryption, the recipient's public key protects it and the recipient's private key recovers it. Certificates bind public keys to identities through an issuer's signature. Invalid-certificate messages can result from expiry, name mismatch, untrusted issuers, or interception; the error alone does not prove an attack. Encryption scope is a separate dimension: full disk, file, database record, or field. Selective encryption does not mean asymmetric encryption.
F|Choose the required property|Choose scope and mechanism|Protect the keys|Validate identity and trust|Plan rotation and recovery
T|Symmetric encryption|A shared secret encrypts and decrypts data. It suits large data volumes; securely distributing and protecting the secret is essential. It does not inherently identify which holder created a message.
T|Asymmetric encryption|A public/private key pair supports operations requiring different related keys. Public-key encryption can protect data for a recipient; modern protocols commonly use asymmetric methods to establish symmetric session keys.
T|Hashing|Maps input to a digest for comparison. An expected digest must come from a trustworthy source. Hashes detect differing bytes, not whether a file is malware-free. Password storage needs a suitable slow salted scheme.
T|Digital signature|A private-key operation binds a message to a signer; a public key verifies it. Changes invalidate verification. It supports integrity and origin authentication, but it does not hide the message.
T|Salting|Adds a unique random value before password hashing so equal passwords do not produce the same stored result. Salts are normally stored with hashes; secrecy of the salt is not the main defense.
T|Key stretching|Increases the cost of guessing each password using a deliberately expensive derivation process. It complements salting rather than replacing uniqueness or strong passwords.
T|CSR|Certificate Signing Request: carries a public key and requested identity details to a certificate issuer. The private key remains protected by the requester and is not sent in the CSR.
T|Certificate revocation|Invalidates a certificate before its scheduled expiry. CRL means Certificate Revocation List; OCSP means Online Certificate Status Protocol. Revocation status is separate from ordinary expiration.
T|HSM|Hardware Security Module: protects cryptographic keys and can perform operations inside a dedicated protected boundary. Centralized server key management is a common use; applications need controlled access to operations.
T|TPM|Trusted Platform Module: a platform-bound security component used for protected keys and measured boot. It can seal disk-unlock material to platform state; it is not interchangeable with an enterprise key service.
T|Record or field encryption|Protects selected database records or values while other content can remain readable. This describes encryption scope, independent of whether symmetric or asymmetric methods support the design.
T|Key escrow|Places protected recovery key material with an authorized custodian. For encrypted data tied to an asymmetric pair, recovery needs the decryption private key, not merely the already-shareable public key.
T|Obfuscation|Makes information harder to interpret without necessarily making recovery depend on a cryptographic secret. Renaming code symbols or masking displayed values does not provide the same guarantees as encryption.
T|Steganography|Hides the existence of information inside another medium. An image may contain a concealed payload without encrypting it. Hiding presence and hiding meaning are separate goals.
T|Blockchain|A ledger groups records into blocks linked by cryptographic hashes, with participants using a consensus mechanism to agree on accepted updates. It can support shared traceability across organizations. It does not prove a physical-world event was entered truthfully; trusted input, access rules, and governance remain necessary.
E|A server publishes a signed update. The signature verifies the publisher and detects modification; it does not prove the program is safe. Separately, a laptop encrypts its disk with a symmetric key protected by a TPM. The organization's web service keeps signing keys in an HSM. The three designs solve distinct problems; the word 'key' alone cannot select the answer.
