P|A vector is the route used to reach a target: email, text, voice, a vulnerable service, removable media, or a supplier. P|A vulnerability is a weakness; an exploit uses it; an indicator is evidence of activity. Separate the source of the weakness from the result. Missing input validation may let a database interpret input as query syntax or a browser execute attacker-controlled script. These are different execution contexts even though both involve untrusted input.
P|Version numbers and error messages are clues, not complete proof. Confirm affected versions, configuration, reachability, and mitigations. Unsupported systems remain risky even if no new alert appears because fixes may no longer exist. A zero-day describes a previously unknown or unaddressed vulnerability at the relevant time; a missed scan detection is a false negative, not automatically a zero-day. Layered mitigations can reduce exposure while a permanent fix is developed.
F|Locate the weakness|Identify where input executes|Verify affected conditions|Reduce exposure|Fix and validate
T|Buffer overflow|Input exceeds a memory buffer's bounds and may overwrite adjacent memory or control data. Memory-safe design and bounds checks address the cause; not every crash proves exploitation.
T|Race condition|A security result depends on timing between operations. A resource can change between a permission check and its use; atomic operations or proper locking reduce the gap.
T|SQL injection|Untrusted input alters a database query's meaning. Parameterized queries separate values from query structure. Web encryption does not fix unsafe query construction.
T|Cross-site scripting|Attacker-controlled script executes in another user's browser in the application's context. Context-aware output encoding and safe rendering prevent data from becoming executable markup.
T|Unpatched software|A fix exists but has not been applied. Validate compatibility, prioritize exposure, deploy through change control, and confirm remediation rather than equating installation attempts with success.
T|End-of-life system|Vendor support or security fixes have ended. Continued operation needs a documented risk treatment and replacement plan; repeatedly scanning does not create missing vendor patches.
T|Default credentials|Factory or broadly known authentication values remain in use. Replace them during provisioning and disable unnecessary accounts; network location alone is not a sufficient safeguard.
T|Cloud misconfiguration|Permissions or service settings expose resources beyond intended scope. A public bucket may leak data without any software exploit because the configuration permits access.
T|VM escape|Code crosses the boundary from a guest virtual machine into the host or other guests through a vulnerability. Guest compromise alone does not prove that the isolation boundary failed.
T|Zero-day vulnerability|A newly discovered weakness lacks prior awareness or a usable fix in the relevant context. It is not simply any unpatched system or any scanner miss.
E|A search field is concatenated into a database query. A crafted input changes which records the database returns: SQL injection. A comment stored in the database later executes script in a visitor's browser: cross-site scripting. Both are input-related, but the execution destination determines the distinction.

P|Interpret evidence before naming an attack. Start with time, system, account, source, destination, action, and result. Many failures against one account suggest password guessing; one common password tried across many accounts suggests spraying. Known leaked username/password pairs suggest credential stuffing. A few failures alone may be ordinary typing mistakes. A successful event after failures deserves correlation, not an automatic claim of compromise.
P|Malware categories describe behavior and may overlap. A Trojan disguises malicious functionality as something desirable; a worm propagates itself; ransomware denies access or extorts; a rootkit hides presence. Intermittent outbound traffic alone cannot prove a keylogger: periodic updates and monitoring agents also communicate. Corroborate with process activity, captured keystrokes, destinations, and endpoint findings. Certificate errors may support on-path investigation but can also be ordinary configuration failures.
F|Read the fields|Find the pattern|Consider normal explanations|Correlate independent evidence|Name only what the evidence supports
T|Ransomware|Encrypts or otherwise denies access and commonly demands payment; some operations also steal data for extortion. Recovery requires containment, trustworthy backups, and removal of the cause.
T|Worm|Self-propagating malware spreads between systems without requiring each victim to manually run the original file. Distinguish propagation behavior from the initial delivery vector.
T|Trojan|Malicious functionality is concealed within apparently useful software. A Trojan need not replicate; the disguise and user expectation are the key features.
T|Rootkit|Uses stealth mechanisms to hide malicious activity or maintain privileged presence. It may alter system views, making trusted offline examination important.
T|Logic bomb|Malicious action is triggered by a condition such as a date or account removal. The delayed trigger distinguishes it from immediate execution.
T|Password spraying|Tries one or a few common passwords across many accounts, often slowly to avoid per-account lockout. Look at account diversity, not only the total number of failures.
T|Credential stuffing|Reuses known breached username/password pairs against another service. It exploits password reuse rather than systematically generating guesses for one account.
T|On-path attack|Interposes between communicating parties to observe or alter traffic. Strong certificate validation and authenticated encryption help; a warning alone does not identify the attacker.
T|Session hijacking|Uses a stolen or manipulated valid session token to impersonate an authenticated session. Reusing a session differs from stealing a password for a fresh login.
T|DDoS|Distributed Denial of Service: many sources exhaust a target's capacity or resources. Multiple origins distinguish a distributed attack from one-source denial of service.
T|Brute force|Attempts many candidate secrets, commonly against a particular account or key. Patterns, rate, and account distribution help distinguish it from spraying and legitimate failures.
T|Keylogger|Captures keystrokes through software or hardware. Staged keyboard records and corresponding process behavior support the finding; outbound traffic alone is insufficient proof.
E|Read 'user=admin result=failed src=192.0.2.40 count=800' as repeated failures against a named account from a source, not eight hundred confirmed compromises. If a separate record shows many passwords against that single account, brute force is plausible. If fifty accounts each receive the same candidate once, spraying fits better. Evidence should support the specific pattern you select.

P|A mitigation must interrupt the actual attack path. Identify whether the exposure is network reachability, excessive permission, untrusted software execution, vulnerable code, or unsafe configuration. Encryption protects content but does not repair the application processing it. Segmentation limits where traffic can travel; least privilege limits what identities can do. These can be combined without being interchangeable.
P|Configuration enforcement is a cycle: define the approved state, assess the device, restrict noncompliant access where necessary, remediate, and reassess. A laptop placed in a restricted network for updates is undergoing posture-based remediation, not sideloading. Isolation is an urgent containment action for a suspected compromised system. Decommissioning retires a system through controlled removal, account cleanup, data treatment, and inventory updates.

T|Segmentation|Separates network zones and controls traffic between them. It reduces lateral reachability when enforcement rules are correct; simply naming two VLANs does not prove filtering exists.
T|Least privilege|Gives identities only the actions and resources needed for their current duties. It applies to humans and service accounts and should be reviewed as roles change.
T|Application allowlisting|Permits only approved applications or code to execute. It addresses execution control rather than merely checking whether an application is already known to be malicious.
T|Patching|Installs fixes for software weaknesses. Test and validate deployment; a reboot-required update or failed installation may leave the vulnerability present.
T|Isolation|Separates a suspect or compromised system from normal communication to limit damage. Preserve needed investigation access and follow the response plan.
T|Configuration enforcement|Checks and restores approved settings or device posture. Noncompliant endpoints may receive restricted connectivity until remediation and revalidation succeed.
T|Decommissioning|Safely retires an asset, removes its access and dependencies, treats its data, and updates records. Merely unplugging it leaves accounts and sensitive storage unmanaged.
T|Encryption|Protects data confidentiality when appropriately implemented and keys are protected. It does not remove malware, fix excessive access, or ensure safe application input.
T|ACL|Access Control List: a rule set permits or denies access based on specified criteria. Network ACLs use addresses, protocols, ports, and direction; order and defaults matter.
T|Disable unnecessary services|Removes unused listening services or features to reduce attack surface. It differs from leaving a service active but hiding it behind a rule.
E|A field laptop returns with missing patches. The access system detects the failed posture check, places it in a remediation segment, installs approved updates, and reassesses before restoring access. Segmentation is the network tool; configuration enforcement describes bringing the device into the required state. The goal and the component are different levels of the same process.
