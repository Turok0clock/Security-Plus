#1.1|Security controls|Classify the implementation category separately from its purpose.|Category → Purpose → Evidence
Technical control|Technology enforces policy.|A firewall automatically drops prohibited packets.~A login service enforces MFA.~A file server enforces access permissions.
Managerial control|Management directs and oversees security.|Leadership approves a security policy.~A committee defines acceptable risk.~The board mandates security assessments.
Operational control|People perform security processes.|A guard checks visitor identities.~Analysts review logs every morning.~Staff conduct incident exercises.
Physical control|A tangible safeguard protects assets.|A fence surrounds a shelter.~A locked cabinet protects equipment.~Vehicle barriers protect a generator.
Preventive control|Stops an unwanted event before success.|An ACL blocks unauthorized connections.~A lock prevents unauthorized entry.~Input validation rejects malicious data before processing.
Detective control|Discovers or records events.|A sensor alerts on motion.~Integrity monitoring reports a changed binary.~An audit identifies account misuse.
Corrective control|Repairs damage or restores an acceptable state.|Staff restore files after ransomware.~A recovery script repairs configuration.~A compromised workstation is rebuilt.
Deterrent control|Discourages attempts through visible consequences.|A sign announces prosecution for trespassing.~Visible guards discourage opportunistic entry.~A banner warns that unauthorized activity is monitored.
Compensating control|Substitutes for a preferred unavailable safeguard.|A legacy system lacks MFA, so an approved restricted jump host provides alternative protection.~An unpatchable appliance receives isolation and extra filtering.~An approved encryption exception is covered by controlled physical storage.
Directive control|Specifies required behavior.|Policy requires reporting lost badges.~A procedure requires locking unattended consoles.~A standard requires vendor accounts to expire.
#1.2|Fundamental security concepts|Identify the property or trust decision the evidence describes.|Identity → Decision → Enforcement → Reevaluate
Confidentiality|Prevents unauthorized disclosure.|An encrypted stolen laptop reveals no records.~Payroll records are readable only by approved staff.~A privacy filter prevents nearby passengers reading a report.
Integrity|Protects against unauthorized alteration.|A modified download fails its hash check.~A changed transaction invalidates its signature.~A database detects tampered records.
Availability|Keeps services accessible when needed.|Redundant power maintains badge service.~Failover keeps an application online.~Traffic scrubbing preserves access during flooding.
Authentication|Verifies a claimed identity.|A user proves possession of a security key.~A badge is validated at a door.~A server proves identity with a certificate.
Authorization|Determines permitted actions.|An authenticated employee cannot open payroll.~A signed-in technician can view but not delete tickets.~A contractor is limited to one folder.
Accounting|Records activity for accountability.|A gateway records administrator commands.~An application logs report downloads by user.~A service records authenticated session duration.
Non-repudiation|Provides evidence linking an action to its signer.|A signed purchase approval supports attribution.~A verified signed submission resolves a sender dispute.~A document signature links approval to a private signing key.
Zero trust|No implicit trust based on location; access is continually evaluated.|An internal laptop must prove identity and posture.~A session is reevaluated after device health changes.~A corporate IP address alone grants no application access.
Policy enforcement point|Enforces access decisions.|A gateway applies a policy engine's deny decision.~A proxy ends a revoked session.~An agent allows only the application authorized by policy.
Honeypot|A decoy attracts and reveals unauthorized activity.|A fake database alerts on access.~A decoy server records attacker commands.~An unused service is deployed to observe exploitation.
#1.3|Change management|Evaluate impact, obtain authorization, prepare rollback, and verify results.|Request → Impact → Approval → Test → Implement → Verify
Impact analysis|Evaluates a change's consequences.|A firewall update is reviewed for effects on video streams.~A migration's customer disruption is estimated.~A new authentication workflow is assessed for business effects.
Change approval|The authorized body permits implementation.|A tested update awaits board authorization.~The service owner signs off on production work.~An engineer waits for the designated authority's decision.
Backout plan|Defines how to restore the previous working state.|Instructions explain restoring the old firewall policy.~An upgrade includes the rollback image and steps.~A migration has an approved reversal procedure.
Maintenance window|An approved period for potentially disruptive work.|An outage is scheduled during low demand.~Network updates run during the agreed overnight period.~An upgrade avoids payroll processing hours.
Version control|Tracks revisions and supports recovery.|Engineers compare two configuration revisions.~Deployment references a particular approved commit.~A team identifies the exact changes made last Tuesday.
Standard operating procedure|Provides repeatable instructions.|Technicians follow approved patching steps.~Operators follow documented certificate renewal instructions.~Backup validation uses a standardized sequence.
Dependency analysis|Finds components that rely on each other.|DNS retirement requires checking application references.~A new certificate must account for pinned clients.~A library update requires identifying dependent applications.
Testing|Checks behavior before broad implementation.|A patch is evaluated on representative staging hosts.~A database migration is rehearsed on a copy.~A new policy is checked with allowed and denied traffic.
Stakeholder communication|Informs affected parties.|The help desk receives outage times and symptoms.~Facilities is notified before badge-system maintenance.~Customers receive the planned service interruption schedule.
Documentation update|Aligns records with implemented changes.|A network diagram is corrected after a server move.~Inventory is revised after firewall replacement.~Operating instructions reflect the new login workflow.
#1.4|Cryptographic solutions|Choose the mechanism that supplies the required property.|Generate → Protect → Trust → Use → Revoke
Symmetric encryption|Uses a shared secret efficiently for bulk protection.|One shared key protects a large backup.~A session uses its negotiated secret for bulk data.~Terabytes must be encrypted efficiently after key exchange.
Asymmetric encryption|Uses a public and private key pair.|A sender encrypts with the recipient's public key.~Decryption keys stay private while encryption keys are distributed.~A recipient alone can decrypt data sent using their public key.
Hashing|Produces a one-way digest for integrity comparison.|A download is compared with a published SHA-256 value.~Evidence copies are compared by digest.~A file change is detected without recovering the original data.
Digital signature|Supports integrity and origin using private signing and public verification keys.|A vendor signs its software update.~A recipient verifies an unchanged signed contract.~A message is linked to its signing key.
Salting|Adds unique random input before password hashing.|Identical passwords yield different stored hashes.~Unique per-user values defeat precomputed rainbow tables.~Each password hash has its own stored random input.
Key stretching|Makes password derivation deliberately expensive.|A verifier increases its work factor.~Repeated derivation rounds slow offline guesses.~Each password attempt requires substantial computation.
Certificate signing request (CSR)|Carries a public key and identity information for an issuer.|A web administrator sends subject details and a public key to a CA.~A host requests a certificate without transmitting its private key.~A certificate authority receives a request to validate and sign.
Certificate revocation|Invalidates a certificate before expiration.|A stolen private key triggers early invalidation.~An employee certificate is withdrawn on termination.~OCSP reports an issued certificate is no longer valid.
Hardware security module (HSM)|Dedicated hardware protects keys and cryptographic operations.|A payment service centralizes protected signing keys.~A CA needs a tamper-resistant signing appliance.~Keys must stay inside a dedicated cryptographic device.
Trusted platform module (TPM)|Device-bound hardware root of trust and key protection.|A laptop binds disk unlock to measured boot.~An onboard chip protects workstation secrets.~An endpoint reports hardware-rooted platform measurements.
#2.1|Threat actors and motivations|Combine resources, access, motivation, and capability.|Actor → Access → Resources → Motivation
Nation-state actor|Pursues strategic goals with substantial resources.|A long campaign steals defense research for geopolitical advantage.~A government-linked group targets foreign infrastructure.~An intrusion supports national intelligence priorities.
Organized crime|Coordinated criminal operations seek profit.|A ransomware group has negotiators and affiliates.~An operation sells stolen card records at scale.~A criminal network runs extortion as a business.
Hacktivist|Attacks promote ideological or political causes.|A site is defaced to protest pollution.~Documents are leaked to advance an activist cause.~Service disruption draws attention to a political message.
Insider threat|Someone with authorized access or knowledge causes harm.|An employee exports designs before resigning.~An administrator abuses privileges to sabotage service.~A contractor deliberately leaks accessible project data.
Unskilled attacker|Relies on existing tools with limited understanding.|A novice runs a downloaded exploit blindly.~A teenager uses a point-and-click attack tool.~An intruder copies commands but cannot adapt them.
Shadow IT|Unapproved technology operates outside normal oversight.|A department uses an unapproved cloud file service.~Staff install an unmanaged router.~A team purchases SaaS without security review.
Financial motivation|Seeks money or saleable assets.|An attacker demands payment to decrypt files.~Stolen accounts are sold for profit.~Invoice payments are diverted to a criminal account.
Espionage motivation|Seeks confidential information for strategic advantage.|An intruder quietly collects manufacturing designs.~A campaign prioritizes diplomatic communications.~Research is stolen while disruption is deliberately avoided.
Disruption motivation|Seeks interruption or destruction.|An attacker wipes systems without demanding payment.~A campaign aims to keep a public service offline.~Sabotage disables industrial scheduling at peak demand.
External actor|Acts from outside the authorized workforce or trust boundary.|An unrelated internet group attacks a public portal.~A hired intruder has no organizational account.~Unknown criminals target an exposed remote-access service.
#2.2|Threat vectors and attack surfaces|Distinguish the delivery method from the payload.|Exposure → Delivery → Interaction → Execution
Phishing|Deceptive messages induce harmful actions.|A payroll email links to a fake login.~A delivery email collects credentials.~A benefits email asks for a password on a linked form.
Smishing|Phishing via text messages.|An SMS claims unpaid tolls.~A bank verification text steals credentials.~A package-redelivery text collects card data.
Vishing|Social engineering via voice.|A caller requests an MFA code while posing as support.~A phone caller pressures accounting to transfer money.~A fake help desk agent asks for a password by phone.
Spear phishing|Targets a specific individual or group with tailored content.|A fraudulent email cites an engineer's current project.~A message references a manager's supplier negotiation.~A small team receives phishing using its internal terminology.
Business email compromise|Abuses trusted business email or workflows.|A compromised supplier mailbox sends new bank details.~An executive's hacked email requests an urgent wire.~An attacker alters payment instructions in a real invoice thread.
Watering hole|Compromises a site intended victims regularly visit.|An engineering forum infects its regular visitors.~An association site delivers targeted malware.~A supplier portal is compromised to reach customer staff.
Typosquatting|Uses mistyped or lookalike domains.|A bank domain is registered with a missing letter.~A misspelled download URL serves malware.~A visually similar site captures misdirected logins.
Removable media vector|Portable storage introduces an attack.|A found USB drive launches malware.~An infected file arrives on a portable drive.~Maintenance media infects an air-gapped host.
Supply chain vector|Trusted suppliers or dependencies carry the attack.|A signed vendor update contains malware.~A package dependency steals credentials.~A compromised vendor platform reaches its clients.
Pretexting|A fabricated role or story persuades the target.|A fake auditor requests personnel records.~An attacker poses as a newly hired employee.~A visitor invents a maintenance emergency to get a badge.
#2.3|Vulnerabilities|Find the weakness that enables the attack.|Weakness → Exposure → Exploit → Impact
Buffer overflow|Excess input overwrites adjacent memory.|A huge string crashes a fixed-buffer program.~Crafted input overwrites a return address.~A service copies unbounded data into limited memory.
Race condition|Timing between concurrent operations changes the outcome.|Two requests redeem one token simultaneously.~A resource changes between checking and use.~Concurrent withdrawals bypass a balance check.
SQL injection|Input changes database query logic.|A tautology in a login field bypasses authentication.~A search appends SQL to expose other records.~Raw concatenated input produces database syntax errors.
Cross-site scripting (XSS)|Injected script runs in a victim's browser.|A saved comment steals session cookies.~A reflected search term executes JavaScript.~A profile field runs script for other users.
Unpatched software|Available security fixes are missing.|An old known flaw with an available patch is exploited.~A scan finds an absent security update.~An appliance lacks a released fix for remote execution.
End-of-life system|Normal vendor security support has ended.|An OS can no longer receive vendor fixes.~A retired appliance remains in production.~A legacy platform's vendor stopped security releases.
Default credentials|Factory credentials remain active.|A camera accepts the published admin password.~An appliance is breached with its setup account.~A controller uses credentials from its installation guide.
Cloud misconfiguration|Insecure cloud settings expose resources.|A storage bucket allows anonymous downloads.~A cloud management port is open globally.~A workload role has unnecessary unrestricted permissions.
VM escape|A guest breaks isolation into its host.|Compromised guest code executes in the hypervisor.~Malware crosses from a tenant VM to its host.~A virtualization flaw lets a guest affect the underlying platform.
Zero-day vulnerability|An exploited weakness lacks an available effective vendor fix.|A new exploited flaw has no patch.~A vendor learns of active exploitation before a fix exists.~Defenders isolate systems pending a fix for a newly discovered exploit.
#2.4|Indicators of malicious activity|Correlate evidence before deciding what attack occurred.|Evidence → Correlation → Hypothesis → Validation
Ransomware|Extorts through encryption or threatened disclosure.|Unreadable files accompany a payment demand.~Changed extensions appear beside a ransom note.~Stolen files will be published unless payment is made.
Worm|Self-propagates between systems.|Malware spreads through exposed services automatically.~An infected host exploits neighbors without user action.~An outbreak expands without additional attachments being opened.
Trojan|Malware is disguised as useful software.|A utility secretly opens remote access.~An apparently useful game installs a stealer.~A fake security tool delivers malware.
Rootkit|Privileged manipulation hides malicious activity.|A kernel component conceals processes.~Hooked system functions hide malicious files.~Compromise persists below ordinary user-level inspection.
Logic bomb|Malicious action is triggered by a condition.|Records are deleted when an employee account disappears.~Sabotage activates on a future date.~A hidden routine wipes data after a missed activation event.
Password spraying|Few passwords are tried across many users.|One common password is tried on hundreds of accounts.~Many users get one failed attempt each.~Guesses are distributed to avoid individual lockouts.
Credential stuffing|Previously stolen username-password pairs are reused.|Leaked external credentials work on company accounts.~A bot tests a breach list against a store login.~Password reuse allows stolen account pairs to succeed.
On-path attack|An intermediary intercepts or modifies communications.|A rogue gateway relays and captures traffic.~An attacker alters responses between client and service.~Connections pass through an unauthorized interceptor.
Session hijacking|A valid session token is reused to impersonate a user.|A stolen cookie provides access without a password.~A leaked bearer token takes over an existing login.~An attacker replays a captured session identifier.
Distributed denial of service (DDoS)|Many sources overwhelm a service.|Thousands of compromised devices flood a site.~A botnet saturates a public API.~Requests from many networks exhaust a target's capacity.
#2.5|Mitigation techniques|Choose the safeguard that directly reduces the attack path.|Identify path → Reduce exposure → Apply control → Validate
Network segmentation|Separates systems and restricts cross-group traffic.|Cameras must not reach payroll directly.~An industrial controller enters a restricted zone.~Guest wireless is isolated from internal services.
Least privilege|Limits permissions to required tasks.|A service account receives only needed read access.~A technician loses unnecessary admin rights.~A contractor can access only the assigned project.
Application allowlisting|Only approved applications may run.|A kiosk executes only approved programs.~Unknown executables are blocked without antivirus signatures.~Endpoints run only software in an approved catalog.
Patching|Installs fixes for known weaknesses.|A tested vendor update closes a server flaw.~An appliance receives the release fixing remote execution.~A vulnerable dependency is upgraded to its corrected version.
Isolation|Contains a suspect system to limit spread.|An infected workstation is quarantined.~A compromised server enters a containment network.~A spreading host's connectivity is restricted.
Configuration enforcement|Maintains approved secure settings.|A tool reverses unauthorized firewall changes.~Endpoints are remediated against hardened baselines.~Policy prevents insecure bucket permissions from persisting.
Decommissioning|Securely retires systems, access, and data.|An unused unsupported server is removed and sanitized.~A redundant application is retired with its credentials.~Old network equipment is wiped before disposal.
Encryption|Protects confidentiality through cryptographic keys.|A stolen backup drive must reveal no records.~Sensitive traffic crosses an untrusted network securely.~A database copy must resist offline reading.
Access control list (ACL)|Rules permit or deny subjects or traffic.|A router limits management access to one subnet.~A directory permission list denies one group.~Packets are filtered by addresses, protocol, and port.
Disable unnecessary services|Removes unused functionality and exposure.|An unused Telnet daemon is disabled.~Unneeded file sharing is removed from a web host.~Unused management interfaces are turned off.
#3.1|Architecture models|Identify who manages each layer and where isolation boundaries exist.|Model → Responsibility → Trust boundary → Exposure
Infrastructure as a service (IaaS)|Provider supplies infrastructure; customer manages guest OS and applications.|A team rents VMs and patches their operating systems.~A cloud customer configures guest firewalls and installs software.~A provider manages physical hosts while the tenant administers its virtual servers.
Platform as a service (PaaS)|Provider manages the application platform; customer supplies code and data.|Developers deploy code without patching the runtime OS.~A managed application platform runs customer code.~A provider maintains middleware while a team builds its application.
Software as a service (SaaS)|Provider operates a complete application.|Staff use a browser-based hosted CRM.~A company configures accounts in a vendor-operated email service.~A subscription delivers a complete online collaboration application.
Shared responsibility model|Security duties are divided between customer and provider.|A cloud tenant must determine who patches each software layer.~A contract clarifies provider infrastructure duties and customer data duties.~A team maps security ownership before moving workloads to cloud.
Infrastructure as code (IaC)|Versioned definitions provision infrastructure.|A reviewed template creates networks and servers repeatedly.~Engineers rebuild an environment from declarative configuration.~Infrastructure changes follow code review and version history.
Microservices|Small independently deployable services form an application.|An application splits ordering and billing into separately deployed APIs.~One service can scale without redeploying the entire application.~A failure in a small independently managed component is contained.
Containerization|Applications share a host kernel while isolating runtime environments.|Several isolated application packages share one operating-system kernel.~A lightweight deployment bundles dependencies without a full guest OS.~A team uses image-based application isolation on a common host.
Serverless architecture|Provider executes event-driven functions and manages underlying servers.|Uploaded files trigger short-lived functions.~A team deploys functions without administering servers.~Billing tracks function execution rather than reserved virtual machines.
Air gap|Physical separation removes direct network connectivity.|An industrial network has no connection to external networks.~Sensitive analysis occurs on a physically disconnected environment.~Data transfer requires controlled removable media because no network path exists.
Industrial control system (ICS)|Controls physical industrial processes with safety and availability constraints.|A plant uses controllers to regulate pressure valves.~Production machinery depends on deterministic control networks.~Security changes must preserve a factory's physical process safety.
#3.2|Enterprise infrastructure security|Place controls where they can inspect or constrain the required traffic.|Boundary → Inspection → Segmentation → Access
Web application firewall (WAF)|Inspects application-layer web requests.|A control filters injection patterns in HTTP requests.~A web service needs protection from malicious request parameters.~An edge device evaluates web payloads rather than only port numbers.
Intrusion prevention system (IPS)|Detects and actively blocks suspicious network activity.|An inline sensor stops packets matching exploit signatures.~A network device automatically drops detected attack traffic.~A control must block malicious traffic as it passes through.
Intrusion detection system (IDS)|Detects suspicious activity and alerts without directly blocking.|A passive sensor alerts on copied network traffic.~Monitoring must observe attacks without altering packet flow.~A tap-fed device raises warnings for known exploit patterns.
Network access control (NAC)|Controls network admission based on identity or device posture.|Unpatched laptops enter a remediation network.~Unknown devices cannot join until checked.~Network access depends on endpoint compliance status.
Jump server|Provides a controlled intermediary for administrative access.|Admins reach internal servers through a monitored management host.~Direct administrator connections from user subnets are prohibited.~Privileged sessions are funneled through one hardened intermediary.
Screened subnet|An isolated network hosts externally accessible services.|Public web servers are separated from the internal database network.~Internet-facing systems occupy a dedicated boundary zone.~A compromise of an exposed service should not grant direct LAN access.
Forward proxy|Acts on behalf of clients making outbound requests.|Employee web requests pass through centralized content filtering.~A gateway hides client addresses from destination websites.~Outbound browsing is mediated by a server representing users.
Reverse proxy|Acts on behalf of servers receiving inbound requests.|A front-end gateway routes internet requests to backend servers.~External clients see one gateway instead of internal application hosts.~TLS termination and request routing sit in front of several web services.
Fail-closed|Failure denies access to preserve security.|An authentication gateway outage blocks new sessions.~A broken security control must default to denied traffic.~A door remains secured during controller failure where approved safety design permits.
Fail-open|Failure permits access to preserve availability or safety.|An inline device failure allows traffic to continue under approved policy.~A critical process must keep communicating if its filter fails.~An access decision defaults to passage during a specifically approved failure condition.
#3.3|Data protection|Consider classification, data state, access, and lifecycle.|Classify → Minimize → Protect → Retain → Dispose
Data at rest|Data is stored on a medium.|A database backup resides on a disk.~Customer records sit in object storage.~A powered-off laptop contains confidential files.
Data in transit|Data is moving between endpoints.|Records are transmitted from a browser to an API.~Replication traffic crosses a WAN.~A file moves between two servers.
Data in use|Data is actively being processed.|A service decrypts records in memory to calculate results.~Sensitive values exist in a running process.~An application manipulates plaintext inside its execution environment.
Tokenization|Replaces sensitive values with surrogates linked through a protected mapping.|A store saves payment tokens instead of card numbers.~A vault maps substitute identifiers to original sensitive values.~An application uses non-sensitive stand-ins recoverable through a secure token service.
Data masking|Obscures selected data elements for display or limited use.|Support sees only the last four card digits.~A report hides portions of personal identifiers.~A screen substitutes asterisks for sensitive fields.
Data loss prevention (DLP)|Detects or blocks unauthorized movement of sensitive data.|An email gateway blocks unapproved transmission of customer identifiers.~A control prevents classified documents being uploaded to personal storage.~Endpoint policy stops copying regulated records to removable media.
Data minimization|Collects and retains only necessary data.|A registration form removes unnecessary birth-date collection.~An application stops gathering location data irrelevant to its purpose.~A service reduces retained customer fields to business essentials.
Data classification|Labels information according to sensitivity and handling requirements.|A record is labeled confidential after assessment.~A company separates public, internal, and restricted documents.~Handling controls depend on assigned sensitivity categories.
Data sovereignty|Data is subject to laws associated with its location or jurisdiction.|A company evaluates legal implications of storing records overseas.~A cloud region choice changes which jurisdiction governs stored data.~A business must respect country-specific requirements for locally stored information.
Geographic restrictions|Limit where data may reside or be accessed.|Policy allows storage only in approved countries.~A cloud deployment is blocked outside selected regions.~Sensitive records may be processed only within a specified national boundary.
#3.4|Resilience and recovery|Distinguish the outage limit from the acceptable data-loss window.|Business impact → Recovery targets → Redundancy → Exercise
Recovery time objective (RTO)|Target maximum time to restore a service.|Payroll must resume within four hours of failure.~An application has a two-hour restoration target.~A recovery plan specifies the permitted service outage duration.
Recovery point objective (RPO)|Maximum acceptable data loss measured in time.|A system can lose no more than fifteen minutes of transactions.~Backups must limit lost changes to one hour.~The business defines how far back recovered data may be.
Hot site|An operational recovery location can take over rapidly.|A staffed alternate site has current systems ready to run.~Recovery requires near-immediate use of prepared infrastructure.~A duplicate operational environment is maintained for failover.
Warm site|Partially equipped recovery location requires further setup or restoration.|An alternate site has hardware but needs current data restored.~Recovery equipment exists but applications need preparation.~A facility is ready for configuration before operations can resume.
Cold site|A location provides basic space and utilities but little configured equipment.|A recovery contract provides empty space with power and networking.~Servers must be delivered before the alternate facility can operate.~A low-cost recovery location lacks ready computing systems.
Immutable backup|Backup data cannot be altered during a defined retention period.|Ransomware cannot overwrite protected historical copies.~A retention lock prevents administrators deleting recent backups.~Backup objects remain unchanged until their protected period expires.
Tabletop exercise|Discussion walks participants through a scenario.|Responders discuss a simulated outage without activating systems.~Leaders review decisions during a hypothetical disaster.~A facilitator asks teams what they would do at each incident stage.
Failover test|Validates transfer to redundant resources.|A team deliberately switches service to its secondary site.~Traffic is moved to a standby system to verify continuity.~Recovery staff demonstrate that the backup environment can carry production load.
Load balancing|Distributes requests across multiple resources.|Incoming requests are spread among healthy servers.~One service uses several active nodes to share demand.~A gateway prevents a single backend from receiving every request.
Diverse power sources|Reduces common-mode power failure risk.|Redundant feeds come from separate providers.~A facility avoids placing both power circuits on one upstream source.~Backup power is independent of the failed utility path.
#4.1|Securing computing resources|Apply baselines and validate the endpoint's actual state.|Baseline → Deploy → Harden → Monitor → Remediate
Secure baseline|Defines approved minimum configuration.|A workstation image has documented required security settings.~New servers are compared with an approved hardening standard.~An organization establishes the minimum acceptable endpoint configuration.
Full-disk encryption|Protects stored disk contents from offline access.|A lost laptop must resist disk removal attacks.~An endpoint encrypts its entire system volume.~A stolen workstation's powered-off drive should not expose files.
Mobile device management (MDM)|Centrally enforces mobile-device configuration and lifecycle controls.|IT remotely locks a lost corporate phone.~A policy requires screen locks on managed tablets.~Administrators enforce device-wide settings across mobile endpoints.
Mobile application management (MAM)|Manages corporate applications and their data.|A company wipes business app data while retaining personal photos.~Policy restricts copying information from a managed app.~Corporate application settings are controlled on a personal device.
Bring your own device (BYOD)|Employees use personally owned devices for work.|Staff access company email on their own phones.~A policy permits personal laptops for business tasks.~Employees provide the hardware used to reach corporate applications.
Corporate-owned personally enabled (COPE)|The organization owns devices and permits personal use.|Company-issued phones also allow approved personal apps.~An employer owns tablets employees may use privately.~Corporate hardware supports business and permitted personal activities.
WPA3|Modern Wi-Fi security with stronger authentication protections.|A new wireless deployment requires SAE rather than legacy PSK exchange.~Wireless policy upgrades to the latest listed personal Wi-Fi security generation.~An access point uses Simultaneous Authentication of Equals.
802.1X|Port-based access authentication.|Switch ports require identity validation before normal network access.~Enterprise Wi-Fi authenticates users through an EAP exchange.~An authenticator consults a backend server before allowing a supplicant onto the network.
Input validation|Checks submitted data against expected format and constraints.|An API rejects an impossible date before processing.~An application accepts only allowed values for a numeric field.~Unexpected input types are refused at the application boundary.
Endpoint detection and response (EDR)|Monitors endpoint behavior and supports investigation and containment.|An agent records process lineage and isolates a suspicious laptop.~Analysts investigate endpoint execution history and terminate malicious processes.~A workstation tool detects behavior and supports remote response actions.
#4.2|Asset management|Track ownership, location, value, and disposition throughout the lifecycle.|Acquire → Inventory → Assign → Monitor → Sanitize → Dispose

Asset owner|Is accountable for an asset's business use and protection decisions.|A department head approves the sensitivity and access needs of its dataset.~Someone must accept business risk for a system.~The accountable business representative determines an asset's requirements.
Asset custodian|Performs day-to-day handling and technical protection.|An administrator implements storage controls defined by the data owner.~Operations staff maintain backups and permissions.~A team carries out approved handling requirements for a dataset.
Asset tagging|Attaches identifiers that support tracking.|A laptop receives a barcode tied to inventory.~Equipment has a unique tracking label affixed.~A technician scans a device identifier during an audit.
Procurement review|Evaluates requirements and risk before acquisition.|Security assesses a new appliance before purchase.~A buyer checks vendor support and update commitments.~A proposed SaaS purchase receives requirements review before contracting.
Software license management|Tracks authorized software entitlements and use.|Installed application counts are compared with purchased seats.~An audit finds deployments exceeding licensed quantities.~A team reclaims unused paid software subscriptions.
Data retention|Defines how long information must be kept.|A schedule specifies when archived records may be deleted.~Policy requires preserving logs for a set period.~Business and legal needs determine a dataset's storage duration.
Sanitization|Makes stored data unrecoverable according to its sensitivity and media.|A drive is securely cleared before reassignment.~A disposal process removes sensitive data beyond normal deletion.~A technician validates that retired media no longer exposes records.
Cryptographic erase|Destroys encryption keys so encrypted data becomes inaccessible.|A self-encrypting drive is retired by securely destroying its key.~Encrypted storage is rendered unreadable through key deletion.~A device is sanitized by eliminating the only decryption material.
Certificate of destruction|Documents that a destruction service completed disposal.|A vendor provides evidence that retired drives were shredded.~An audit requires a record of completed media destruction.~A disposal contractor issues proof tied to the destroyed asset identifiers.
#4.3|Vulnerability management|Validate findings and prioritize exposure and business impact.|Discover → Validate → Prioritize → Remediate → Rescan
Credentialed scanning|Uses authorized credentials for deeper system inspection.|A scanner signs in to inspect installed patch levels.~Assessment reads protected configuration with an approved account.~Authenticated access reveals weaknesses invisible to an external scan.
Noncredentialed scanning|Examines externally visible behavior without logging in.|An assessor sees only exposed ports and service responses.~A scan tests what an unauthenticated attacker can observe.~No account is supplied for the vulnerability scan.
False positive|A reported issue is not actually present.|A scanner flags an outdated banner despite a verified backported fix.~Manual review proves the reported vulnerability does not apply.~An alert identifies a weakness that validation cannot reproduce because it is absent.
False negative|A real issue is missed.|An unreported vulnerability is confirmed by manual testing.~A scanner reports clean results despite an exploitable flaw.~An assessment fails to identify a weakness that is present.
CVSS severity|Standardized technical vulnerability severity scoring.|A report assigns a numerical technical severity score.~Analysts compare published base severity values.~A vulnerability's attack complexity and impact contribute to its standard score.
Risk-based prioritization|Combines severity with exposure, exploitation, and business impact.|An internet-facing exploited flaw outranks a higher-score isolated lab issue.~A critical business service receives earlier remediation due to active exploitation.~Asset value and reachable attack paths change patch order.
Compensating mitigation|Reduces exposure while a direct fix is unavailable.|An unpatchable system is isolated and tightly filtered.~A vendor delay requires temporary access restrictions.~A critical legacy service uses added monitoring and segmentation until replacement.
Rescanning|Verifies remediation effectiveness.|A team scans again after patch deployment.~The original finding is retested after configuration changes.~Closure requires evidence that the vulnerability no longer exists.
Static application security testing (SAST)|Examines code without running the application.|A pipeline checks source code for unsafe data handling.~Developers scan code paths before execution.~An analyzer identifies weaknesses in application source.
Dynamic application security testing (DAST)|Tests a running application from the outside.|A scanner sends attack inputs to a deployed web app.~A test evaluates responses from a live service.~Security testing interacts with an executing application without its source code.
#4.4|Security monitoring|Collect useful signals, correlate them, and act on validated findings.|Collect → Normalize → Correlate → Alert → Investigate
Security information and event management (SIEM)|Aggregates and correlates security logs.|Analysts combine authentication and firewall events in one platform.~A tool correlates alerts across multiple log sources.~Centralized event analysis detects a pattern spanning several systems.
Security orchestration automation and response (SOAR)|Automates response workflows across tools.|A playbook enriches an alert and opens a ticket automatically.~A response platform calls several security tools in sequence.~Validated events trigger automated containment and case management.
Log aggregation|Collects logs from many sources.|Server logs are forwarded to one repository.~A team consolidates appliance events for searching.~Central storage receives records from many endpoints.
Alert tuning|Adjusts detection rules to improve useful signal.|Analysts reduce repetitive benign alerts with verified exceptions.~A detection threshold is revised after reviewing normal behavior.~Noisy rules are refined without discarding relevant attacks.

#4.6|Identity and access management|Follow identity lifecycle, authenticate strongly, then grant minimal access.|Provision → Authenticate → Authorize → Review → Deprovision

Account deprovisioning|Removes access when it is no longer authorized.|A departing employee's accounts and tokens are disabled.~A contractor's project access ends at contract completion.~Offboarding revokes credentials and active sessions.
Access recertification|Periodically verifies that access remains appropriate.|Managers review employees' current permissions quarterly.~An audit asks owners to confirm privileged memberships.~Stale entitlements are removed after formal access review.
Passwordless authentication|Authenticates without a reusable typed password.|A user signs in using a device-bound passkey.~A security key proves possession through a challenge response.~A biometric unlocks a cryptographic credential used for login.

Eradication|Removes the cause and malicious artifacts.|Responders remove persistence and malicious binaries.~A compromised image is replaced after evidence collection.~An exploited vulnerability is fixed as part of eliminating the intrusion.

#5.2|Risk management|Assess likelihood and impact, choose a response, and assign an owner.|Identify → Analyze → Respond → Monitor
